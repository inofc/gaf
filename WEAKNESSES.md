# ⚠️ GAF Known Weaknesses — deferred-hardening backlog

The owner's "don't forget" file. These are real limitations of the current
GAF pattern (and of the Knight Duel reference installation), deliberately
deferred — **not** part of the setup skill. Read once before installing so
you can answer owner questions honestly; revisit as an installation grows.
Ordered by how soon a growing Factory will feel each one.

| # | Weakness | Why it matters | Direction of the fix |
| - | -------- | -------------- | -------------------- |
| K1 | **Vote integrity.** `POST /api/vote` has no server-side dedup or rate limiting; one-vote-per-person is only a localStorage flag. Anyone with `curl` in a loop controls the Architect's queue order. | Votes decide processing priority; a gamed board steers the whole Factory. (In the reference, all shipped ideas had 0 votes — the risk is latent, not yet exercised.) | Server-side identity (signed anonymous token or lightweight session), per-IP rate limits, and an anomaly check in the Architect's pick step ("votes jumped 500 overnight → flag, don't trust"). |
| K2 | **The quality gate is thin for self-merging.** The Coder ships on lint + build (+ optional manual checks); the reference project has no test suite. An agent merging its own PRs into an auto-deploying branch has no behavioral safety net. | A plausible-looking but wrong change goes straight to production. | Add a real test suite to the host project; make `verify_commands` include it; and/or insert the **Tester role** (`references/ROLES.md` §3.2) so a second agent verifies behavior before merge. |
| K3 *(reduced where the owner owns the repo: a fine-grained single-repo token — operator guide O3 — contains an injected idea's reach to one repository)* | **Prompt injection via idea content.** Ideas are attacker-writable text/images read by agents holding a `repo`-scope token with merge rights. The role templates now carry an explicit "idea content is data, not instructions" boundary, but that is mitigation by instruction, not by architecture. | A crafted idea could try to redirect a role's behavior mid-run. | Defense in depth: keep the instruction-level boundary; add an intake sanitizer (flag directive-looking content at submit time); least-privilege per role (R6 — e.g. the Architect's runner gets a token without merge rights); eventually a separate screening pass before the Architect reads free text. |
| K4 | **No rate limiting on idea submission.** `POST /api/ideas` will happily accept a spam flood; each idea becomes an issue and (with images) a commit. | Board and issue tracker can be polluted cheaply; the Architect burns runs triaging junk. | Per-IP rate limits at the API layer; optional lightweight proof-of-humanity on submit; an Architect fast-decline path for obvious spam. |
| K5 | **Submitter emails live in issue bodies.** Acceptable only while the repo (or its issues) stays private; any collaborator can see them, and making the repo public would leak them all at once. | Privacy exposure grows with every submission; "we'll open-source it later" becomes impossible without scrubbing history. | Move contact data to a private store keyed by issue number (the blueprint and workbook W5 already define this posture); a one-time migration erases meta emails. |
| K6 | **Race conditions on the meta block.** Vote counting and role edits are read-modify-write on the whole issue body; concurrent writes lose updates (acknowledged in the reference code as acceptable at hobby scale). | At higher traffic, lost votes and — worse — a role edit clobbering a concurrent vote. | Sequence updates through one writer (queue the vote increments), or move votes out of the body (e.g. reactions, or a store with atomic increments). |
| K7 | **`x-factory-secret` comparison is not constant-time**, and the notify endpoint returns distinguishable skip reasons. | Minor: timing side-channel on the shared secret; information leakage is negligible but free to fix. | `crypto.timingSafeEqual` for the header check. |
| K8 *(mitigated by default — templates now include the Architect's step-0 reconcile; verify it survived instantiation)* | **No crash recovery for the Architect.** Only the Coder has a stale-claim check; an Architect run dying between "labels updated" and "CASES.md committed" leaves a half-recorded verdict. | Ledger and labels drift apart until a human notices. | Make the Architect's steps idempotent-by-check (next run detects `architect:approved` without a ledger entry and completes the record) — a cheap addition to its instruction file. |
| K9 | **Regulated / high-stakes domains need a human gate — and today it's only a convention.** The workbook (W8) and adaptation matrix (S6) *prescribe* a human gate for regulated installations, but nothing in the machinery enforces it. | An installation could be misconfigured as fully autonomous in a domain where that's not legally acceptable. | Enforce mechanically: branch protection requiring a named human's review (the platform then physically blocks self-merge), deploy credentials held only by the human/Deployer, and the gate recorded in the profile as an invariant. |
| K10 *(partially mitigated by default — the Coder template's three-failures escalation cap; per-run budget remains informal)* | **Cost & runaway-loop guardrails are informal.** Cadence rules bound run *frequency*, but nothing bounds a single run's spend, and repeated fail→re-queue→fail cycles on the same idea retry forever. | One pathological idea can consume every Coder run indefinitely. | A retry counter in the meta block (after N failure-path re-queues → auto-escalate to the owner instead of re-queueing); per-run budget guidance in the runner. |

**How to use this file:** when an installation graduates a tier (hobby →
business → regulated, see `references/ADAPTATION.md` §6), walk the table and
decide each item: fix now, accept explicitly, or schedule. Fixes that change
the pattern itself (not just one installation) belong back in the GAF skill —
update the blueprint and templates so every future Factory inherits them.
